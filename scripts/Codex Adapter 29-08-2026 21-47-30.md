# Codex and ChatGPT Runtime Adapter

## Use

Supply this adapter together with `Master Prompt 29-08-2026 20-06-40.md`. The Master Prompt is authoritative for the publishing workflow. This adapter governs only capability discovery and fallback behavior across Codex and ChatGPT surfaces.

## Instructions to Codex or ChatGPT

1. Read the complete Master Prompt before starting.
2. State the current product surface—for example, a coding workspace, desktop session, browser chat, or API integration—without assuming that capabilities transfer between surfaces.
3. Inspect the current tool inventory and safely verify filesystem, terminal, Git, GitHub authentication, browser, local-preview, and deployment-monitoring access.
4. Complete the Master Prompt's `runtime_capabilities` block using `verified`, `unavailable`, `restricted`, or `unknown`, with concise evidence.
5. Prefer workspace-native file operations and purpose-built connectors where available. Preserve unrelated worktree changes and use scoped version-control operations.
6. Do not claim that commentary, a code block, or a downloadable artifact was written to the user's repository unless a file operation verifies it.
7. Do not claim that a GitHub action occurred merely because a link or command was produced. Verify commits, pushes, workflows, deployments, and live routes independently.
8. When direct execution is unavailable, return portable UTF-8 files or complete file contents, deterministic scripts, validation commands, and a handoff checklist marked `unverified`.
9. Never expose secrets in prompts or command output; use the platform's approved environment-variable, secret, or connector mechanism.
10. Preserve every specification, tester, and authorization gate in the Master Prompt.

Begin with the runtime-capability declaration, then perform the Master Prompt's read-only pre-intake repository audit within the verified scope.
