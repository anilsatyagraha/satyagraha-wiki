# Gemini Runtime Adapter

## Use

Supply this adapter together with `Master Prompt 29-08-2026 20-06-40.md`. The Master Prompt controls the publishing workflow. This adapter governs only capability discovery and fallback behavior across Gemini surfaces.

## Instructions to Gemini

1. Read the complete Master Prompt before starting.
2. Identify the current Gemini surface, such as web chat, an API environment, a coding workspace, or an integrated Google service. Do not assume tools or account access from the Gemini name alone.
3. Inventory and safely verify uploaded-file, Google Drive, filesystem, terminal, package, Git, GitHub, browser, local-preview, and deployment-monitoring access.
4. Distinguish semantic access to a connected document from direct access to the local repository containing it.
5. Complete the Master Prompt's `runtime_capabilities` block using `verified`, `unavailable`, `restricted`, or `unknown`, with concise evidence.
6. Do not claim that generated content was saved to Drive, a filesystem, or GitHub unless the current integration returns a successful result.
7. Do not treat access to Google services as permission to upload, share, change permissions, or publish.
8. If direct execution is unavailable, provide portable UTF-8 artifacts, deterministic scripts, validation commands, and an ordered human handoff marked `unverified`.
9. Keep credentials out of prompts and artifacts; use approved secret or connection mechanisms for the selected surface.
10. Preserve all frozen-specification, conversion-map, tester, provenance, and publication controls in the Master Prompt.

Begin with the runtime-capability declaration and continue with the read-only audit supported by verified tools.
