# SEO Metadata Decision

## Objective

Add relevant site-wide search metadata to every generated public HTML file without changing visible legal text or other body content.

## Research evidence

- India Code identifies the statute as **The Code of Civil Procedure, 1908** and organizes it through Parts, Orders, Rules, schedules and appendices.
- Current search results consistently use the terms Civil Procedure Code, CPC, Orders and Rules, civil litigation and Indian legal research.
- Google Search Central states that `meta name="keywords"` is ignored for Google indexing and ranking. It is retained only as requested compatibility metadata; the implementation does not claim a ranking benefit.
- Google advises against keyword stuffing in titles. Existing page titles and visible content therefore remain unchanged.

## Approved phrase set

1. `Code of Civil Procedure 1908`
2. `Civil Procedure Code India`
3. `CPC Orders and Rules`
4. `Indian civil litigation`
5. `Indian legal research`
6. `Satyagraha Law Group`

The first five are the researched subject phrases. The sixth is the required organization name.

## Implementation decision

- Inject one managed metadata block immediately before `</head>` in every generated `.html` file.
- Include one `meta name="keywords"`, one `meta name="author"`, and one `WebPage` JSON-LD block containing the phrase set and publisher.
- Derive the JSON-LD page name and URL from existing title, canonical or Open Graph metadata.
- Preserve existing metadata, including `noindex` on legacy redirect pages.
- Run the injector after Quartz in GitHub Actions and expose the same command through `npm run seo`.
- Make injection idempotent by replacing only the marked managed block.

## Risks and guardrails

- **Risk:** Unsupported claims about ranking. **Guardrail:** State that Google ignores meta keywords and make no ranking guarantee.
- **Risk:** Keyword stuffing. **Guardrail:** Do not rewrite titles, descriptions, headings or visible text.
- **Risk:** Legal content changes. **Guardrail:** Compare the entire post-`</head>` tail before and after injection and stop on any difference.
- **Risk:** Duplicate metadata after repeated builds. **Guardrail:** Require exactly one marked block per page.
- **Risk:** Redirect pages become indexable. **Guardrail:** Preserve existing robots directives unchanged.
- **Risk:** Manual edits disappear on rebuild. **Guardrail:** Keep the transformation in a committed deterministic script and deployment workflow.

## Validation standard

1. Build the complete site.
2. Record pre-injection hashes for every complete post-`</head>` tail.
3. Inject metadata across every generated HTML file.
4. Require the exact phrase set in both keyword metadata and JSON-LD.
5. Require one author tag naming Satyagraha Law Group.
6. Parse every managed JSON-LD block.
7. Compare post-injection tails against the recorded hashes.
8. Run the injector again and require zero changed files.
9. Re-run repository tests and `git diff --check`.

## Remaining uncertainty

Search engines determine ranking independently and may ignore or rewrite metadata. This implementation guarantees consistent valid metadata and content preservation, not a particular search position.
